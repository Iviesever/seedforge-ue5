## Read-only engine evidence and hypotheses

- UE 5.8 LaunchEngineLoop.cpp sets `FViewport::SetGameRenderingEnabled(true, 3)` for standalone startup, explicitly hiding the first few presents while driver caches initialize. Both rejected start/combat captures occurred inside this first-three-frame interval. This is a concrete rendering boundary to test, not evidence that every black-frame cause is solved.
- The viewport-rendered delegate fires before screenshot processing, but being called on frame 0 is not enough to establish a normal presented gameplay frame.
- HUD clipping is selective: larger/status draws lose left prefixes while smaller control text can remain intact; the title can clip independently in the win frame. It persists after camera-cut correction and is being diagnosed separately, without assuming PNG corruption or silently accepting it.
