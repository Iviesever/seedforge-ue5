# SF-IRA-007/009 request and applied identity implementation plan

> **Execution:** `executing-tasks` inline, RED → minimal fix → verification → independent commit.

**Objective:** Pending/new/failed runs never expose previous applied hashes, and successful apply logs identify the actual subsystem request independently from the run generation.

**Architecture:** Preserve the public one-argument direct-layout apply API. Add a private two-argument apply overload receiving the actual completion RequestId. The direct public path explicitly cancels pending generation and uses source request 0 (no subsystem completion); only successful apply stores AppliedRequestId. Snapshot exposes this readonly applied identity for production diagnostics and later input trace verification.

**Constraints/non-goals:** Same checkout, one UE writer, Engine read-only. No generator/hash/state-machine transition redesign. No global skill memory. Starting/rollback HEAD: `4b68da82c89f5dc1776a264fd94bb8dcd5d1b216`.
