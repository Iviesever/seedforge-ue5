# UE 5.8 全自动作品集冲刺：需求单

## 原始诉求

用户已安装 Unreal Engine 5.8，希望在 Codex Pro 20x 于 2026-09-05 15:30（UTC+8）到期前，最大化利用当前几乎完整的使用限额，由 Codex 完成全部项目代码；用户不参与编写代码。最终目标是产出能为 C++ 游戏开发实习和面试加分的公开作品集项目。

## 项目位置与协作边界

- 项目根目录固定为 `D:\program\SeedForge`。
- 此后的 SeedForge 工作全部保存在该目录内，不修改 `D:\program` 下的其他项目。
- 协作上限为一个主智能体和最多两个辅助子智能体；子智能体并非必须使用。
- UE 的完整 Build、Test、Cook、Package 只允许一个写进程运行。

## 已确认约束

- 时间窗口：2026-09-03 11:35 至 2026-09-05 15:30，约 51 小时 55 分。
- 开发环境：Windows、UE 5.8.0 二进制安装、Visual Studio Community 2026、MSVC、Windows SDK。
- 用户不编写代码；所有代码、测试、构建脚本、文档与验证均由 Agent 完成。
- 必须保留可审查的 C++ 源码、自动化测试、构建日志和可运行交付物。
- 关键范围应尽量使用文本源码与引擎自带资源，降低手工 `.uasset`、动画、美术和关卡编辑依赖。
- 不以无意义消耗使用限额为目标；额度用于高价值设计、实现、测试、审查与修复。

## 成功标准

到截止时间前至少交付：

1. 一个可独立打开、构建并运行的 UE 5.8 C++ 仓库。
2. 一个可观察的端到端灰盒体验，而非仅有孤立算法或空插件。
3. 核心算法和 UE 集成的自动化测试与命令行验证入口。
4. Win64 候选构建；若打包链受环境阻塞，至少保留已验证 Editor 构建及完整阻塞证据。
5. README、架构说明、验收矩阵、测试/构建证据、已知限制和 AI 协作说明。
6. 面向用户的代码导读与面试学习材料，避免把无法解释的生成代码当作个人能力证明。

## 非目标

- 开放世界、商业级美术、复杂动画、完整多人在线服务、账号、匹配或背包系统。
- 教程或 Marketplace 框架换皮。
- 依赖用户临时手工修代码、制作资产或处理构建错误。
- 用 MQB 替代 UnrealBuildTool。

## 待批准方向

推荐 `SeedForge`：确定性异步地牢生成 Runtime 插件，加一个完全使用引擎基础图元的纯 C++ 灰盒可玩样例。技术蓝图获用户批准后才进入实现。
