# Architecture

## Design goal

SeedForge separates deterministic layout/encounter data, bounded path/state work, asynchronous ownership, gameplay scene application, portable evidence, and Editor tooling so each boundary can be reviewed and tested independently. Phase 3 detail is in `PHASE3_ARCHITECTURE.md`.

## Runtime generation path

### `FSeedForgeGenerator`

Input is only a `uint64` seed and `FSeedForgeConfig`. A fixed SplitMix64 stream proposes bounded integer rectangles. Accepted rooms are canonically sorted; consecutive centers receive deterministic L-shaped corridors. The first room center is the entrance, and the farthest Manhattan-distance center is the exit with canonical iteration as the tie break.

`ValidateConfig` exposes the same bounded configuration contract to import and benchmark callers. `ComputeCanonicalHash` applies byte-defined FNV-1a to the algorithm marker, seed, ordered rooms, ordered corridor cells, and endpoints. Version 0.2.0 deliberately preserves all 0.1.0 golden hashes.

### `FSeedForgeLayout` and `FSeedForgeValidator`

The layout is a plain C++ value containing seed, rooms, corridor cells, endpoints, and hash. `GetCanonicalWalkableCells` expands rooms, appends corridors, sorts by Y/X, and removes duplicates.

Validation fails in a deterministic order: room count, bounds, overlap, entrance, exit, then four-neighbor BFS connectivity. `TSet` is used only for membership; its iteration never controls serialized or hashed output.

### `FSeedForgeAsyncCoordinator` and `USeedForgeWorldSubsystem`

`Start` cancels the prior token, assigns a monotonic request id, and launches value-only work with `UE::Tasks`. The Game Thread callback applies only if shared state exists, shutdown has not occurred, the token is live, and the id is still newest. Cancellation suppresses stale application; it does not forcibly stop a monolithic generator already executing.

The subsystem owns this coordinator at the UObject boundary, captures itself weakly for apply, clears delegates on `Deinitialize`, and never blocks the Game Thread waiting for workers.

### Visualization and gameplay demo

`FSeedForgeVisualizationPlanner` converts canonical cells into floor and exterior-wall transforms. `ASeedForgePreviewActor` applies them to two HISM components using the Engine cube asset and supports an apply-only gameplay mode. `ASeedForgeGameplayCoordinator` consumes the newest applied layout, creates a deterministic encounter, owns every run actor/timer/state transition, and supplies a read-only HUD snapshot. `ASeedForgeDemoGameMode` selects native Controller/HUD classes and creates lighting/coordinator in C++; the only map is generated by script.

### Deterministic gameplay model

`FSeedForgeEncounterPlanner` selects one player, one exit, three Cores, and five enemies from canonical walkable cells using explicit score/order/tie rules. Its version/hash is independent from the preserved layout identity. `FSeedForgeGridPathfinder` runs four-neighbor unit-cost A* with Manhattan heuristic, fixed East/South/West/North neighbors, `(F,H,Y,X)` selection, and an expansion budget. `FSeedForgeRunStateMachine` exclusively owns Generating/Playing/Won/Lost/Restarting transitions and Core/exit eligibility.

Enemy Pawns move every frame but search only on a bounded 2 Hz coordinator timer. Combat, player/enemy HP, cooldowns, pickup proximity, exit unlock, restart cleanup, and smoke are centralized in the coordinator; actors never reconstruct topology or terminal state.

## Portable evidence path

### `FSeedForgeLayoutDocument` and `FSeedForgeLayoutCodec`

The document binds schema/generator versions, generation configuration, and layout identity. Export emits compact JSON in an explicit field order. Seed and hash are decimal strings, avoiding the precision loss of JSON's common double-number model.

Import distinguishes missing fields, wrong types, unsupported schema or versions, invalid unsigned values, order-dependent data, hash mismatch, invalid configuration, and invalid topology. Unknown fields are ignored for forward-compatible readers. Collections are normalized before canonical hash comparison. Full rules are in `LAYOUT_FORMAT.md`.

### `FSeedForgeLayoutDiffer`

Diff compares two valid documents as structured values rather than text. It records seed/hash/config/endpoint changes and sorted added/removed room and walkable-cell sets. Reversing the inputs swaps the set differences. Human and fixed-order JSON summaries carry both identities and exact counts.

### `FSeedForgeBenchmarkRunner`

The runner validates bounds, performs unmeasured warm-up generations, measures each requested seed with `FPlatformTime`, and reports total/min/nearest-rank median/P95/max. A byte-defined aggregate combines each measured seed and canonical hash; it proves which outputs were observed independently of timing. See `BENCHMARKING.md`.

## Editor-only layer

`USeedForgeReportCommandlet` provides unattended `Generate`, `Diff`, and `Benchmark` modes with explicit output paths and non-zero failures. It owns filesystem I/O; the Runtime codec remains free of file and UObject access.

`FSeedForgeEditorModule` registers one Nomad tab. Its Slate Inspector consumes existing Runtime APIs, displays seed/hash/count/timing evidence, and exports canonical JSON. A command-line-only capture hook opens this same widget, captures it through `FSlateApplication`, and exits for deterministic visual QA. No Blueprint or content asset is created.

## Complexity

- Room placement: `O(A * R)` for attempt budget `A` and accepted rooms `R`.
- Overlap validation: `O(R^2)`.
- Walkable expansion/sort: `O(W log W)`.
- Connectivity: expected `O(W)` after canonical cells are built.
- Codec export/import: `O(R + C)` plus JSON parsing and collection sorts.
- Structural diff: `O((R + W) log(R + W))` because both sides are sorted before a linear merge.
- Benchmark: `O(N * generation)` and `O(N log N)` for timing distribution sorting.
- Encounter ranking: `O(W log W)` over canonical walkable cells.
- A*: current open-set scan is worst-case `O(V^2)` time and `O(V)` storage, bounded per request.

The corridor `AddUnique` path remains intentionally simple and can approach quadratic behavior in corridor count. It is acceptable for the scoped 48x48 lab, not a claim of production scalability.

## Determinism boundary

Guaranteed and tested for the same SeedForge algorithm/encounter version, configuration, Win64 target, and UE 5.8 toolchain: topology, initial encounter IDs/cells, canonical JSON bytes, layout/encounter hashes, A* request result, structural diff order, and aggregate benchmark identity.

Not guaranteed: a complete real-time playthrough, input/timer/physics behavior across frame rates, timings, render pixels, future versions, other platforms/compilers, or a precise cancellation instruction boundary.
