# AI assistance and authorship

## Disclosure

SeedForge 0.1.0 and 0.2.0 were specified by the user and implemented, tested, debugged, packaged, visually inspected, and documented by Codex using GPT-5.6 Sol. The user explicitly requested full vibe coding and did not participate in writing the code during the delivery window.

The user supplied the career goal, deadline, workspace and agent limits, and authority to approve the scoped Phase 2 blueprint. Codex chose implementation details, wrote C++/tests/scripts/docs, ran UE 5.8, inspected reports and images, and assembled evidence.

## What the user may honestly claim

An accurate portfolio description is:

> I scoped and supervised an AI-assisted UE 5.8 C++ engineering project. I can reproduce its tests and packages, explain its deterministic/async/evidence architecture, and use its artifacts to study production-style verification.

After the user personally studies and changes the system, they may additionally describe that specific change and the understanding demonstrated by it.

## What must not be claimed

- The user independently hand-wrote this implementation.
- Generated tests alone prove the user's C++ or UE skill.
- The project is production-ready, cross-platform, a complete game, or free of future defects.
- Timing observations are universal benchmarks.
- AI assistance can be omitted where an employer, course, contest, or platform requires disclosure or forbids it.

## Responsible interview preparation

Before presenting the project, the user should be able to:

1. Reproduce build, focused tests, report generation, plugin packaging, and Win64 smoke.
2. Explain fixed RNG state, canonical ordering, hash bytes, validator order, and BFS.
3. Explain cancellation versus interruption, request generations, and weak UObject boundaries.
4. Explain why `uint64` values are JSON strings and why import hashes normalized data.
5. Explain set-diff symmetry, nearest-rank P95, warm-up, and aggregate benchmark identity.
6. Make one personally authored test-first change and defend its trade-offs.

The final point is the strongest bridge from “AI-produced repository” to credible personal engineering skill.
